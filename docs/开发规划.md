> 配套设计：`产品设计.md` · 原型：`prototype/index.html`

**进度：P0 ✅ · P1 ✅ · P2 ✅ · P3 ✅ · P4 ✅ · P5 ✅ · P6 待开始**

## 0. 重构范围一句话

| 维度 | 现状 | 目标 |
|---|---|---|
| 页面 | 10 个（含 3 个登录页 + 1 个假编辑页） | 10 个（登录保留 1 个空壳；详情 / 生成 / 作答 / 结果 替换掉注册、退出与假编辑） |
| 导航 | 7 项，含「题目编辑」这类假目的地 | 4 项 + 1 个低频维护入口 |
| 接口 | 0 个真实对接（全是 mock） | 35 个接口中实际使用 32 个（不用 `K2`；`Q8`/`Q11` 有封装，但详情页用 `Q5` 一次取回标签与知识点） |
| 数据层 | `api/recognize.ts` 假任务 | `question / label / knowledge / review / statistics` 五个模块 |
| 类型 | 混在一起 | DTO（camelCase）与 Entity（snake_case）严格分开 |

**不做的**：登录鉴权、导出打印、批量操作、单题练习（均无接口，见设计文档 §1.2）；服务端 OCR 不做 —— 识别放在浏览器里（tesseract.js），后端只收最终题干。

## 1. 为什么按这个顺序做

```
P0 地基 ──► P1 题库 ──► P2 录入 ──► P3 复习卷 ──► P4 分析 ──► P5 整理 ──► P6 打磨
                │                        ▲
                └──── 详情页的标签/知识点 ─┘（P5 只是批量维护，不阻塞）
```

- **题库先行**：详情页是录入结果的验证处，也是标签/知识点挂载的唯一入口。题库不通，后面都没法验收。
- **录入其次**：它依赖题库详情来确认「存进去的东西对不对」。
- **复习卷第三**：依赖题库有真实数据，且是全产品交互最重的一块（自评打分）。
- **分析只读**：`K3`/`L7` 直接渲染，工作量小，但需要前面的数据才有意义。
- **整理最后**：低频维护，接口独立，不阻塞主线；但标签创建能力要在 P1 就内联到详情页（`L3`），否则录题时打不了标签。

**验收**

**实施记录（已完成）**

| 项 | 落地方式 |
|---|---|
| 框选 | `components/capture/RegionPicker.vue`，坐标存百分比；拖拽按帧合并（rAF），八个控制点缩放，`< 24px` 的框丢弃 |
| 单页布局 | 去掉步骤条，左图右题：`capture__stage` 粘住、右侧卡片滚动；新框自动把对应卡片滚进视野，点卡片点亮图上的框（`active` 双向绑定），窄屏 ≤1100px 退回上下排列 |
| 裁切 | `utils/crop.ts`：`cropToBlob` 按百分比回算原图坐标，输出 JPEG（长边限 2200px）；`toBlob` 已包 Promise |
| 逐题卡片 | `components/capture/CaptureCard.vue`，缩略图用 CSS 定位原图（零延迟），不额外生成图片 |
| 草稿 | `utils/captureDraft.ts`，key `capture:draft:v1`；图压到 1400px / JPEG 0.72 再存，配额不足时降级为「只存文字」并提示 |
| 失败隔离 | 建题成功即写 `card.questionId`，重试**跳过 `Q3`**，只补 `Q6` / `Q9` / `Q12` —— 否则重试会重复建题 |
| OCR | `utils/ocr.ts`：tesseract.js 单例 + 串行队列，`chi_sim + eng`，`langPath` 指向 `4.0.0_fast`（约 4 MB，首次下载后走浏览器缓存），`OEM.LSTM_ONLY` + `preserve_interword_spaces`；离开页面释放 wasm |
| 文本解析 | `utils/ocrText.ts`（纯函数）：一行多选项按标记位置切、选项折行接续、剥离题号、过滤页码杂物；题型按选项数与「多选 / 不定项」关键词推断 |
| 识别时机 | 框松手即入队（`regionIdKey` watcher，拖动不改 id 所以不会重复触发）；框改过则卡片提示「结果过期」；手动「重新识别」覆盖前先确认；识别期间用户已手打则不覆盖 |
| 识别质量 | 实测印刷体中文可用，公式/上下标/希腊字母必错（`π` → `Tr`、`f(x)` → `fx)`、`（ ）` → `(+)`）。因此**不做纠错**，只做结构规整；选项 key 保留原字母不重排 —— 重排会让「答案是 B」对到别的选项上 |
| 离线部署 | 把 `worker.min.js`、`tesseract-core-*.wasm.js`、`chi_sim/eng.traineddata.gz` 放进 `public/ocr/`，用 `VITE_OCR_WORKER_PATH` / `VITE_OCR_CORE_PATH` / `VITE_OCR_LANG_PATH` 指向同源目录；不配则走 jsdelivr + projectnaptha |
| 题干渲染 | `utils/markup.ts`：`markdown-it`（`html: false`、`breaks: true`、`linkify: false`）+ `@mdit/plugin-katex`。`renderMarkup` 走块级（题干），`renderInlineMarkup` 走行内（选项，避免 `<p>` 嵌进 `<button>`）；`hasMarkup` 用「渲染结果里有没有 `<p>`/`<br>` 以外的标签」判断要不要显示预览，不拿正则猜语法。排版在全局 `styles/markdown.css` 的 `.md-body`（`v-html` 拿不到 scoped），`markup` 单独成块 364 kB / gzip 121 kB，不进首屏 |
| 公式输入 | `CaptureCard` 有 12 个常用片段（插到光标处，已在 `$…$` 内只插 TeX）+ 实时预览；`QuestionBody` 统一渲染，详情 / 作答 / 结果都生效；详情页编辑态也有预览 |
| 列表降级 | `previewStem` 剥掉 Markdown 标记（链接留文字、公式留 TeX、`**` 与列表符号去掉），列表里不会出现一屏星号；不处理 `_斜体_`，因为 `a_n` 这种下标太常见 |
| 未做 | 整图放大查看：图片宽度被容器 `max-width: 100%` 卡住，单纯加 `zoom`/`scale` 只是把同一个受限尺寸再放大，看不到更多细节；真要放大得让画布超出容器并自己处理滚动，与框选坐标耦合太紧，本期不做（已从设计文档移除） |

**验收**
- 生成 5 题 → 作答 → 交卷 → 结果页得分率与自评一致

- 同一份卷重复交卷 → 409 提示「已经交过了」并跳结果页

- 全部题都选「不评分」→ 交卷成功，结果页显示「—」而不是 0%
- 结果页逐题分数与抽屉里的自评一致（刷新后仍一致）

**坑**：
- `O2` 不返回答案 → 作答页不能有「看答案」
- `answerrecord` 无时间 → 结果页不要显示日期
- `O5` 不校验状态 → 前端必须自己挡

**实施记录（已完成）**

| 项 | 落地方式 |
|---|---|

## 4. 贯穿性技术约定

### 4.1 请求层

```ts
// 每个接口一个函数，命名 = 文档编号语义
export function listQuestions(status?: 'unresolved' | 'resolved'): Promise<QuestionSummary[]>
export function searchQuestions(keyword: string, page = 0, size = 10): Promise<SearchResponse>
export function getQuestion(id: number): Promise<QuestionDetail>
export function updateQuestion(id: number, patch: QuestionPatch): Promise<QuestionDetail>
```

- `updateQuestion` 的 `patch` 只放**用户改过的字段**（`null` 语义 = 不改，传 undefined 会被 JSON 丢掉，正好）
- 所有 query 参数用 `URLSearchParams`，`undefined` 跳过
- 上传用 `FormData`，part 名写死常量 `'img'` / `'file'`（错了会 400）

### 4.2 类型

| 来源 | 命名 | 处理 |
|---|---|---|
| DTO | camelCase | 直接用 |
| Entity | snake_case | 直接用，**不要**转成 camelCase 模型 |

理由：接口文档明确说「这是真实行为，统一会是破坏性变更」。前端做映射层会在后端变更时变成隐性 bug 源。组件里按来源取字段，虽然丑，但准确。

### 4.3 三态

每个数据页统一结构：

```
loading → SkeletonList
error   → ErrorBar（message + 重试）
empty   → EmptyState（说明 + 一个下一步按钮）
```

用 `useAsync(fn, deps)` 封装，避免每页手写 `ref(loading) / ref(error)`。

### 4.4 日期与数字

- `LocalDateTime` 字符串 `2026-11-16T18:10:56` 直接 `new Date()` 在 Safari 会 NaN → 用 `replace(' ', 'T')` 后手动切分格式化，不依赖 `Date` 解析
- 得分率 `0.64` → `64%`；`null` → `未练习`
- 分数去掉尾随 0：`32.00` → `32`

### 4.5 开发期后端

文档明确说「真实 MySQL / MinIO / ES 往返未验证」。建议：

1. 先按文档写一个 30 行的 mock server（Express / json-server）跑起来，保证前端可独立推进；
2. 后端就绪后只改 `vite.config.ts` 的 proxy 目标，不动业务代码；
3. mock 数据用文档里的示例 JSON，字段风格（snake/camel）必须一致，否则联调时才发现字段取错。

## 8. 上次接通接口时踩过的坑（直接复用，别重踩）

项目记忆里有一版「只换数据源、不动 IA」的接通记录。那版的产品结构已经被这次设计取代，但下面这些**技术性坑**是接口本身决定的，这次一样会遇到：

| 坑 | 处理 |
|---|---|
| `content` 是**字符串入参、对象出参** | 请求前 `JSON.stringify`，读取时已是对象；不转换直接 400 |
| `content.question_id` / `userid` 不可信 | 构造时一律写 `null`，ID 只取响应顶层 `questionId` |
| `v-model.number` 清空输入框得到空串 | 题量等数字参数要兜底成默认值，否则空串发出去 400 |
| Vue 模板里 `v-if="current"` 不收窄类型 | 用 `computed` 派生 `currentItems`，别在模板里 `current.items` |
| 删掉最后一页最后一条后页码越界 | `page = min(page, pageCount)` 夹住 |
| `v-model` 绑的对象必须在渲染前铺好 | 进作答页时预填 `answers`，不在模板里临时创建 |
| 时间字符串无时区 | 直接按本地解析，**不要补 `Z`** |
| 删除/改名返回 `false` 仍是 200 | 当「目标不存在」提示，不当错误 |
| 图片 30 分钟过期 | `<img @error>` 显示过期态，重拉接口而不是缓存 |
