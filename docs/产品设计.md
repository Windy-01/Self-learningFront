# 错题整理平台 · 产品页面设计（全量重构）

> 依据：`doc/API接口文档.md`（4 个 Controller / 34 个接口）
> 版本：v2 设计稿 · 2026-11-16
> 范围：信息架构、导航、页面结构、交互规则、接口映射。**不含代码实现细节**，实现见 `开发规划.md`。

---

## 0. 一句话结论

当前前端是按「拍照 → OCR 识别 → 校对 → 入库」这条链路搭的，但**后端没有 OCR 接口**：识别只能放在浏览器里做（tesseract.js，本机 wasm，图片不出设备），识别结果必须由用户对着裁切图核对。接口里同样没有登录、没有单题练习，`Q4` 也不支持按标签筛题。

重构后的产品是四件事：**把题存进来（录入 / 题库）→ 把题标清楚（标签 / 知识点）→ 抽一份卷子做（复习卷）→ 看哪里弱（分析）**。

导航从 7 项收敛到 4 项 + 1 个低频入口；页面数量基本不变，但**职责完全不同**——3 个登录页和 1 个「假编辑页」被换成详情 / 生成 / 作答 / 结果；同时**删掉 14 项无接口支撑的入口与按钮**。

## 1. 设计依据：接口能力边界

设计的第一原则是「**界面上每个按钮都必须有接口能兑现**」。下表是先做完的能力盘点，后面所有页面都由它推导。

### 1.1 能做（界面可以给入口）

| 用户动作 | 接口 | 备注 |
|---|---|---|
| 看题库全部题目 | `Q4` | 不分页，前端分页 |
| 搜题干 / 选项 | `Q1` | ES，近实时（约 1 秒延迟），分页 |
| 看题目详情（含答案、统计） | `Q5` | 唯一能看到答案的地方 |
| 改题干 / 答案 / 来源 / 状态 | `Q6` | 局部更新，`null` = 不改 |
| 删题 | `Q7` | 物理删除，级联 |
| 挂 / 摘标签 | `Q9` / `Q10` | 幂等 |
| 挂 / 摘知识点 | `Q12` / `Q13` | 幂等 |
| 看某题作答历史 | `Q14` | 无时间字段 |
| 传图 | `Q2` | 预签名地址 **30 分钟过期** |
| 建题 | `Q3` | **必须带图，一图一题** |
| 标签增删改查 / 合并 | `L1`–`L6` | 系统标签只读 |
| 知识点增删改查 | `K1`–`K7` | 系统知识点只读，**无合并** |
| 生成复习卷 | `O1` | 支持 `tagId` / `knowledgePointId` 筛选 |
| 看复习卷题目 | `O2` | **不返回答案** |
| 交卷 | `O4` | 客户端自评 `score` / `maxScore` |
| 作废 / 删除复习卷 | `O5` / `O3` | 作废不校验状态，前端兜住 |
| 复习卷历史 | `O6` | 不分页 |
| 知识点掌握度 | `K3` | 已按最弱优先排序 |
| 标签统计 | `L7` | 题数倒序；同时给题数、做过题数、通过率 |
| 学情总览 | `S1` | 跨域汇总：待解决 / 已解决 / 做过题数 / 作答次数 / 总得分率 |

### 1.2 做不了（界面**不能**给入口）

| 想做 | 为什么不行 | 设计上的处理 |
|---|---|---|
| 登录 / 注册 / 退出 | `AuthFilter` 固定 principal = 1，无鉴权接口 | 删掉注册与退出；**登录页保留为空壳**（不接接口，点「进入工作台」直接放行），后端接上鉴权后不用重建路由与版式 |
| 拍照后自动识别（OCR） | 后端无识别接口 | 识别改在**浏览器内**做（tesseract.js，`chi_sim + eng`）：框选后自动识别、结果可改。公式、上下标、希腊字母不可靠，**不承诺识别率**，保存前必须核对 |
| 建无图题 | `Q3` 的 `file` 必填 | 每题必有一张图；纯文字题用「截图/空白图」绕过（见 4.4） |
| 一题多图 | `Q3` 只收一个 `file`，`Q6` 覆盖 `imageKeys` 需已知全部 key | v1 一题一图；多图列进「待补接口」 |
| 换题目的图 | 详情只回 `url`，不回 `key`，无法安全覆盖 | 不做「换图」，需要换图就重建题目 |
| 按标签 / 知识点筛题库 | `Q4` 只认 `status`；`Q1` 只认 `keyword` | **题库页不提供这两个筛选**；标签/知识点的唯一下钻动作是「生成复习卷」 |
| 单题练习 / 错题重做 | `recordPracticeAnswer` 无 Controller | 详情页**不放**「练一题」按钮 |
| 批量删除 / 批量打标 | 无批量接口 | 列表页不做多选 |
| 导出 PDF / 打印排版 | 无接口 | 不做导出（`window.print` 出来的排版不可控，不如不做） |
| 作答草稿保存到服务端 | 无接口 | **localStorage 本地暂存**，交卷才落库 |
| 交卷后看标准答案 | `O2` 不返回答案快照 | 结果页给「查看原题」出口，答案在 `Q5` |
| 作答时间 / 复习耗时 | `answerrecord` 无时间列 | 不展示任何「用时」「最近练习时间」 |

### 1.3 接口的「怪脾气」如何影响交互

| 接口行为 | 设计对策 |
|---|---|
| `Q4` 不分页、返回全量 | 前端分页 20 条/页；页面顶部提示总数 |
| `Q1` 新建后约 1 秒才搜得到 | 搜索框旁常驻一句「刚保存的题目可能需要 1 秒后才搜得到」；搜索无结果时给「查看全部题目」而不是「没有这道题」 |
| 图片地址 30 分钟过期 | 图片 `<img>` 加载失败时显示「图片已过期 · 刷新」，刷新只重拉当前接口，不做本地缓存 |
| `{"deleted": false}` 也是 200 | 统一按「目标已不存在」提示，不弹错误 |
| `Q6` 的 `null` = 不改 | 表单只提交「用户真正改过的字段」，避免误清空 |
| `O5` 作废不校验状态 | 已提交的卷**不显示**作废按钮 |
| `Q14` 无时间 | 作答历史按「第 N 次」编号，不显示日期 |
| `content.question_id` 不可信 | 前端所有 ID 只取响应顶层 `questionId` |

## 2. 信息架构

### 2.1 导航结构

```
错题本
├── 工作台        /                     今天该干什么
├── 题库          /questions            所有题目 + 搜索
│   └── 详情      /questions/:id        看题 / 改题 / 打标 / 删题
├── 复习卷        /review               卷子列表
│   ├── 生成      /review/new           抽题组卷
│   └── 作答      /review/:id           做题 → 自评 → 交卷 → 结果
├── 学情分析      /analysis             哪个知识点最弱
├── ──────────
└── 整理          /organize             标签 / 知识点维护（低频）
```

**导航全部在顶栏**（品牌右侧），分隔线把「日常动线」和「低频维护」分开；顶栏右侧是 `录入题目`（全局主行动）、主题切换、设置。

> 没有侧栏。本站只有 5 个目的地，一层顶栏就放得下 —— 240px 的侧栏会为了 5 个链接长期吃掉 17% 的横向空间，而题库/作答/分析页都更想要宽度。收窄到 900px 以下时导航退化为纯图标（`title` + `aria-label` 兜住可访问性），560px 以下连「录入题目」也退化为图标按钮。

### 2.2 为什么这样分

| 决策 | 理由 |
|---|---|
| 导航只留 4 项 | 用户日常只走「存题 → 做题 → 看弱项」，其它都是支撑动作 |
| 「题目编辑」不再是一级导航 | 编辑是详情页的一个**状态**，不是目的地。原来点进去是一片空白表单，用户不知道该编哪道题 |
| 「标签管理」并进「整理」 | 标签和知识点是同一类东西（分类维度），拆两个页面会让用户在两处找同一个功能；合并后用 Tab 区分，**合并标签**这类高级操作也有了归属 |
| 「整理」放在分隔线右侧 | 低频维护，不能和日常动线抢注意力 |
| 不做顶栏全局搜索 | 搜索只对题库有意义，顶栏再放一个等于两个入口做同一件事 |
| 标签/知识点的下钻 = 生成复习卷 | `Q4` 不支持按标签筛题，但 `O1` 支持。所以「点标签看题」这个动作在产品里被重新定义为「用这个标签组一份卷子」——**这是接口真正能兑现的用户意图** |

### 2.3 核心动线

```
① 存题
   拍/传图 → 框选切题 → 逐题填题干·答案·标签 → 提交（每题一图）

② 做题
   工作台看到「待完成卷」/ 分析页点「专项练习」
   → 生成复习卷（按标签或知识点，薄弱优先）
   → 逐题作答（本地暂存）
   → 交卷（逐题自评打分）
   → 结果页看得分率 → 点某题看原题答案

③ 维护
   题库搜关键词 → 打开详情 → 改题干/答案/状态 → 挂标签
   整理页 → 合并重复标签 / 删掉废弃知识点
```

## 3. 全局约定

### 3.1 状态反馈

| 场景 | 表现 |
|---|---|
| 加载中 | 骨架屏（列表）/ 按钮内 loading（提交）。**不用整页遮罩** |
| 请求失败 | 页内错误条：`错误原因` + `重试`。401 不存在，不用处理 |
| 空数据 | 空态组件：图标 + 一句「现在是什么情况」 + 一个「下一步做什么」的按钮 |
| 危险操作 | 二次确认弹窗，文案写清后果（「删除后不可恢复，作答记录一并删除」） |
| 成功 | 轻提示（2 秒自动消失），不做弹窗 |
| 离开保护 | 录入页、作答页有未提交内容时，路由离开前确认 |

### 3.2 错误文案映射

| HTTP | 界面文案 |
|---|---|
| 400 | 直接用后端 `error` 字段（如「题干 JSON 不合法」） |
| 404 | 「这道题不存在，可能已被删除」→ 引导回题库 |
| 409 | 「这份卷子已经交过了」→ 跳结果页 |
| 500 | 「服务暂时不可用，请稍后重试」+ 重试按钮 |
| 0（没发出去） | 「连不上服务，检查设置里的 API 地址」→ 打开设置 |

### 3.3 视觉语言（沿用现有）

单色体系，无彩色：黑 / 灰 / 白，层次靠明度差 + 1px 描边。语义色（成功/警告/危险）也用灰阶，仅靠**文案和图标**区分。圆角 3–6px，阴影极轻。

状态标签一律用文字 + 描边胶囊，不用颜色：
`待解决`（实线深框）/ `已解决`（虚线灰框）/ `未评分`（虚线灰框）/ `系统`（浅底）。

### 3.4 数字格式

- 得分率：`0.6400` → 显示 `64%`（整数百分比）
- 分数：`32.00 / 50.00` → 显示 `32 / 50`
- 时间：`2026-11-16T18:10:56` → 显示 `11-16 18:10`
- `score_rate = null` → 显示 `未练习`（**不显示 0%**，两者含义完全不同）

## 4. 页面规格

### 4.1 工作台 `/`

**目标**：一进来就知道「现在该干什么」。

```
┌ 工作台 ────────────────────────────────────────────────┐
│ 今天有 2 份卷子没做，3 道题待整理                        │
│                                                          │
│ ┌ 待解决题目 ┐ ┌ 待完成复习卷 ┐ ┌ 累计得分率 ┐            │
│ │    12     │ │      2      │ │    64%    │            │
│ └───────────┘ └─────────────┘ └───────────┘            │
│                                                          │
│ ┌ 继续学习 ───────────────┐ ┌ 最薄弱的知识点 ─────────┐ │
│ │ 三角函数专项  10题  待做 │ │ 三角恒等变换  52%  练 › │ │
│ │ 期中错题      8题   待做 │ │ 导数应用      未练 练 › │ │
│ └─────────────────────────┘ └────────────────────────┘ │
│                                                          │
│ ┌ 最近入库 ──────────────────────────────────────────┐  │
│ │ 已知函数 f(x)=x²，则 f(1) 等于…     11-16 18:10  › │  │
│ └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

| 区块 | 数据源 | 交互 |
|---|---|---|
| 待解决题目 | `S1.unresolved_count` | 点击 → 题库（带 status 筛选） |
| 待完成复习卷 | `O6?status=0` 取 `length`（**不截断**，列表只展示 3 条） | 点击 → 复习卷「待完成」Tab |
| 累计得分率 | `S1.score_rate`（= `total_score / total_max_score`） | 为 null 时显示 `—` |
| 继续学习 | `O6?status=0`，最多 3 条 | 「继续作答」→ `/review/:id` |
| 最薄弱知识点 | `K3` 前 3 条（已按升序） | 「练 ›」→ `/review/new?knowledgePointId=` |
| 最近入库 | `Q4` 按 `createdAt` 倒序前 5 | 点击 → 详情 |

> 计数一律取 `S1`，**不在前端对 `Q4` 全量列表再数一遍**：`Q4` 现在不分页，但一旦加分页，前端自己数出来的「待解决」会静默变成「当前页的待解决」。`S1` 还有 `attempted_questions`（做过的题数）与 `attempt_count`（已评分作答次数），这两个数 `Q4` 里根本没有。

**空态**（题库为空）：整页换成三步引导卡——`① 拍一张试卷 ② 框选题目并填写 ③ 生成第一份复习卷`，只有第 ① 步可点。

**不做**：原来那个「近 7 天做题量直方图」。`answerrecord` 没有时间字段，这张图永远只能是假的。

### 4.2 题库 `/questions`

**目标**：找到那道题。**唯一目标**。

```
┌ 题库                                    共 37 道          ┐
│ [🔍 搜题干或选项…        ] [全部|待解决|已解决]          │
│                                                          │
│ ┌──────────────────────────────────────────────────────┐│
│ │ ▢ 已知函数 f(x)=x²，则 f(1) 等于（  ）                ││
│ │   单选 · 待解决 · 11-16 18:10                   打开 ›││
│ ├──────────────────────────────────────────────────────┤│
│ │ ▢ 求函数 y=2sin(2x+π/3) 的最小正周期…                ││
│ │   解答 · 已解决 · 11-15 09:22                   打开 ›││
│ └──────────────────────────────────────────────────────┘│
│                                         ‹ 1 2 3 4 ›      │
└──────────────────────────────────────────────────────────┘
```

| 元素 | 说明 |
|---|---|
| 搜索框 | 输入 400ms 后走 `Q1`；清空回到 `Q4`。搜索态下顶部出现一条「搜索模式 · 共 N 条 · 退出搜索」 |
| 状态筛选 | 三个分段按钮 → `Q4?status=`。与搜索互斥：搜索时禁用并说明（`Q1` 不支持 status） |
| 列表行 | 缩略图（有图时）+ 题干 2 行 + 元信息一行 + 右侧「打开 ›」。**整行可点** |
| 分页 | 前端分页 20/页（`Q4` 全量返回；`Q1` 用服务端 `page/size`） |
| 排序 | 默认 `createdAt` 倒序。不做排序切换（`Q4` 无排序参数，前端排序会与分页打架） |

**为什么不在这里放标签筛选**：`Q4` 不返回标签，`Q1` 不认标签。硬做只能逐题拉详情（N+1 请求），或者拿一个永远筛不准的结果。**宁可没有，也不给假按钮。**

**空态**：
- 无任何题目 → 「题库还是空的」+「录入第一道题」
- 搜索无结果 → 「没搜到含「xxx」的题目」+「退出搜索」+ 一句「刚保存的题目可能需要 1 秒后才搜得到」

### 4.3 题目详情 `/questions/:id`

**目标**：看全这道题，并就地改它。

```
┌ ‹ 返回题库                                               ┐
│ ┌ 题目 ───────────────────────┐ ┌ 信息 ──────────────┐ │
│ │ [ 图片 ]                     │ │ 状态  待解决  [标记]│ │
│ │                              │ │ 来源  2026秋期中考  │ │
│ │ 已知函数 f(x)=x²，则 f(1)    │ │ 创建  11-16 18:10  │ │
│ │ 等于（  ）                    │ │ 得分率 60%（2 次）  │ │
│ │                              │ │────────────────────│ │
│ │ A. 1   B. 2   C. 4   D. 8    │ │ 标签               │ │
│ │                              │ │ [三角函数 ×] [+ 添加]│ │
│ │ ── 答案 ──                    │ │────────────────────│ │
│ │ A                            │ │ 知识点             │ │
│ │                              │ │ [三角恒等变换 ×][+] │ │
│ └──────────────────────────────┘ └────────────────────┘ │
│ ┌ 作答历史 ────────────────────────────────────────────┐ │
│ │ 第 2 次  我的答案 B   0 / 5                          │ │
│ │ 第 1 次  我的答案 A   5 / 5                          │ │
│ └──────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

**两种模式**：查看态 / 编辑态（右上角「编辑」切换）。编辑态下题干、选项、答案、来源变成输入框，底部出现「保存 / 取消」。保存只提交**改动过的字段**（`Q6` 的 `null` 语义）。

| 动作 | 接口 | 说明 |
|---|---|---|
| 加载 | `Q5` | 404 → 空态「这道题不存在」 |
| 保存编辑 | `Q6` | `content` 需序列化成字符串；改题干后提示「搜索索引稍后更新」 |
| 标记已解决 / 待解决 | `Q6` (`status`) | 一个按钮切换，不弹窗 |
| 挂标签 | `L1`/`L2` 搜索 + `L3` 内联新建 + `Q9` | 弹层里输入即过滤，无匹配时第一行是「新建「xxx」」 |
| 摘标签 | `Q10` | chip 上的 ×，点击即摘，不确认（可重挂） |
| 挂 / 摘知识点 | `K1`/`K4`/`K5` + `Q12`/`Q13` | 同上 |
| 删除 | `Q7` | 确认弹窗：「删除后不可恢复，该题的 N 条作答记录与统计一并删除」 |
| 作答历史 | `Q14` | 按「第 N 次」编号；`score` 为 null 显示「未评分」 |

**不放的按钮**：
- 「练一题」—— 无接口
- 「换图」—— 详情不返回 `key`，无法安全覆盖
- 「查看解析」—— 答案本身就在页面上，再给一个入口是重复

### 4.4 录入 `/capture`

**目标**：把一张卷子变成 N 道题。这是全产品交互最重的一页。

**单页左右布局**（图钉住、题滚动，不跳页）：

```
┌────────────────────────────────┬──────────────────────────────┐
│ 图片缩略条  ＋                  │ 题目 3 道 · 已保存 1 / 3     │
│ ┌────────────────────────────┐ │ ┌──────────────────────────┐ │
│ │  试卷图（直接拖拽画框）      │ │ │ 1  待填写     展开 / 收起 │ │
│ │    ┌──────┐   ┌──────┐      │ │ │ 题干 [textarea]          │ │
│ │    └──────┘   └──────┘      │ │ │ 题型 ▾   答案 [       ]  │ │
│ └────────────────────────────┘ │ │ 选项 A B C D             │ │
│ 已框 3 道 · 识别中 1            │ │ 标签 / 知识点 / 来源      │ │
│                                │ └──────────────────────────┘ │
│                                │ [ 保存剩余 2 道 ]（吸底）     │
└────────────────────────────────┴──────────────────────────────┘
```

**为什么是「框选」而不是「整图建题」**：`Q3` 一图一题。如果一张卷子只建一道题，用户得把卷子裁成 10 张图再传 10 次——所以必须在前端切。**这是现有接口下唯一能实现「一次拍照录多题」的路径。**

| 区域 | 细节 |
|---|---|
| 选图 | 还没有图片时整页是一个拖放区；有图后拖放区收进缩略条右侧的 `＋`。支持点击 / 拖拽 / 粘贴截图，可一次多张。文件只在浏览器里，**不上传** |
| 框选 | 在图上拖拽画矩形，可画多个；每个框立刻生成一张右侧卡片。框太小（< 24×24px）自动忽略。拖八个控制点可缩放框本身（不做整图放大：那会和百分比坐标打架，见下）。**松手即在本机识别**：单题裁切 → OCR → 按行拆出题干与 A/B/C/D 选项 → 推断题型 |
| 联动 | 画完一个框，右侧对应卡片自动滚进视野并展开；点卡片头部反过来点亮图上的框（`scrollIntoView({block:'nearest'})`，已经在视野里就不动） |
| 卡片 | 每道题一张，字段见下。识别结果只是草稿：题干/选项都可直接改；改过框以后卡片提示「框已调整 · 建议重识别」 |

**为什么把三步并成一页**：框完立刻要改题干，而题干对不对必须对着原图看。分步时用户要在「图」和「表单」之间来回切，裁切缩略图又太小，看不清公式。并成一页后左图右题、框和卡片互相点亮，才是这个任务真实的样子。窄屏（≤1100px）自动退回上下排列。

**OCR 的边界**（前端识别绕不开的现实）：

- 引擎：`tesseract.js`（wasm），语言 `chi_sim + eng`，模型首次约 4 MB，之后走浏览器缓存；**图片不上传**，识别完再随建题请求提交裁切图。
- 能认：印刷体中文正文、常见标点、阿拉伯数字。
- 认不准：公式与上下标（`f(x)` → `fx)`）、希腊字母（`π` → `Tr`）、括号与填空线、挤在一行且没有标点的选项。
- 所以：**不做自动纠错**（猜错一个字符比留着原样更难发现）；题型按选项数量推断，多选靠 `多选 / 不定项` 关键词，其余一律按单选，用户可改。
- 选项 `key` 保留识别到的字母、只去重不重排 —— 重排会让「答案是 B」对到另一个选项上。
- **公式不靠识别**：OCR 认不出公式，题干里用 `$…$` 手写 LaTeX。卡片提供 12 个常用片段（上下标 / 分式 / 根号 / 积分 / 求和 / 希腊字母 / 关系符）与实时预览，点一下插到光标处，已经在 `$…$` 里就只插 TeX。详情页、作答页、结果页统一用 KaTeX 渲染，非公式部分照常转义。

**题干的写法：Markdown + LaTeX**

`content.stem_markup` 按 Markdown 解析，公式用 `$…$` / `$$…$$`。这不是为了排版好看，而是录题时真正需要表达的就那么几样，Markdown 恰好全覆盖：

| 写法 | 效果 | 用在哪 |
|---|---|---|
| `**文字**` | 加粗 | 题干、选项 |
| `- ` / `1. ` | 无序 / 有序列表 | 题干 |
| `` `代码` `` | 行内等宽 | 题干、选项 |
| `> 引用` | 左侧竖线 | 题干 |
| 竖线分隔 + 分隔行 | 表格 | 题干 |
| `$x^2$` / `$$\frac{a}{b}$$` | 行内 / 块级公式 | 题干、选项 |

- **预览**：录入卡片、详情页编辑态的题干下面，只要渲染结果和原文不一样（出现加粗、列表、公式、代码、表格……）就自动多出一块「预览」；纯文字不显示 —— 预览和输入框长得一样时，它只是白占地方。判断方式是渲染后看有没有 `<p>` / `<br>` 以外的标签，不用正则去猜语法（`若 |x| < 1` 会被猜成表格，`1. 下列说法` 又确实是列表）。
- **安全边界**：`markdown-it` 关掉 `html`，原文里的 `<img onerror=…>` 一律当文字显示，`javascript:` 链接被 `validateLink` 拦下；唯一注入 `v-html` 的是渲染器的输出。题干是用户自己的数据，但自己的数据也不该成为 XSS 的入口。
- **列表里降级成纯文本**：题库 / 复习卷列表只显示一行，`previewStem` 会剥掉 Markdown 标记（链接留文字、公式留 TeX、`**` 与列表符号去掉），不会出现一屏星号。
- **选项走行内渲染**：选项里不该有段落，所以用 `renderInline`，避免 `<p>` 嵌进 `<button>` 被浏览器拆开。
- 排版样式放在全局 `styles/markdown.css` 的 `.md-body` 上：`v-html` 注入的节点拿不到组件 scoped 属性，样式只能全局定义；尺寸用 `em`，同一个类在 14px 的题干和 13px 的预览里都合适。

**卡片字段 → 提交时怎么落库**

| 字段 | 必填 | 落库方式 |
|---|---|---|
| 裁切图 | ✅ | `Q3` 的 `file`（canvas 导出的 Blob） |
| 题型 | ✅ | `content.type` + `choice_mode` |
| 题干 | ✅ | `content.stem_markup`（Markdown + LaTeX，见上节） |
| 选项 | 选择题必填 | `content.options[{key,markup}]` |
| 答案 | 否 | 建题后 `Q6` 的 `answer` |
| 标签 | 否 | 建题后逐条 `Q9` |
| 知识点 | 否 | 建题后逐条 `Q12` |
| 来源 | 否 | 建题后 `Q6` 的 `source`（可「应用到本批全部」） |

**提交编排**（每题串行，单题失败不影响其他）：

```
for each 卡片:
  POST /api/question/upload (file + content)   → questionId
  if 答案    → PUT /api/question/{id}  { answer }
  if 来源    → PUT /api/question/{id}  { source }
  for 标签   → PUT /api/question/{id}/label/add?tagId=
  for 知识点 → PUT /api/question/{id}/knowledge/add?knowledgePointId=
```

界面上表现为：底部一条进度 `正在保存 3 / 5`，完成后汇总「成功 4 · 失败 1」，失败的卡片标红并可单独重试。

**题型切换的界面变化**：
- 单选 / 多选 → 显示选项编辑器（默认 A–D，可增删，`choice_mode` 自动设 `single`/`multiple`）
- 填空 / 解答 → 隐藏选项区
- 题型是自由字符串，不在枚举里时按「解答」处理（`content.type` 原样提交）

**离开保护**：有任何未提交卡片时，返回/关闭前确认。

### 4.7 作答 `/review/:id`（`status=0`）

> 作答与结果**共用一个地址**：`/review/:id` 按卷子状态渲染。交卷后页面就地变成结果页，
> 用户刷新也不会看到一份已交卷子的作答界面。

**目标**：安安静静做完这套卷子，然后给自己打分。

```
┌ ‹ 三角函数专项                    3 / 10            [交卷] ┐
│                                                          │
│ ┌ 3 ───────────────────────────────────────────────────┐│
│ │ 已知函数 f(x)=x²，则 f(1) 等于（  ）                  ││
│ │ [ 图片（如果有） ]                                    ││
│ │                                                      ││
│ │  ○ A. 1    ○ B. 2    ○ C. 4    ○ D. 8                ││
│ │                                                      ││
│ │ 在题库中打开这道题 ›                                   ││
│ └──────────────────────────────────────────────────────┘│
│                                                          │
│ 已答 3 题 · 答案自动暂存在本机                            │
└──────────────────────────────────────────────────────────┘
```

**关键规则**

| 规则 | 原因 |
|---|---|
| 一次显示一题（上一题 / 下一题），不做长列表 | 长列表在手机上要滚很久；一题一屏更专注。顶部有题号导航点 |
| 答案存 `localStorage`，键 `sheet:{id}:answers` | 没有保存接口，刷新/关页面必须能恢复 |
| **不显示标准答案** | `O2` 不返回答案快照 |
| 每题给「在题库中打开这道题 ›」 | 需要看答案时的唯一出口（`Q5` 有 `answer`） |
| 作答控件按 `content.type` 渲染 | 单选/多选 → 选项按钮；其它 → textarea |
| 页头右侧常驻「交卷」 | 不要求答完才能交（服务端允许空答案）；底部留给上一题 / 下一题，不重复放交卷 |
| 「作废」是页头右侧的 ghost 按钮 + 二次确认 | 低频且不可逆；已提交的卷子不渲染这个按钮（`O5` 不校验状态，前端自己挡） |

**交卷 = 自评**。点「交卷」打开评分抽屉：

```
┌ 交卷前，给每题打个分 ────────────────────────────────┐
│ 1  我的答案 A   满分 [5]  得分 [▮▮▮▮▮] 5      [全对] │
│ 2  我的答案 B   满分 [5]  得分 [▮▮▯▯▯] 2      [半对] │
│ 3  未作答       满分 [5]  得分 [▯▯▯▯▯] 0      [零分] │
│ 4  我的答案 …   满分 [ ]  得分 [ ]           [不评分]│
│                                                      │
│ 合计 7 / 15 · 得分率 47%          [取消] [确认交卷]  │
└──────────────────────────────────────────────────────┘
```

- 每行三个快捷档：全对 = 满分、半对 = 满分×0.5、零分 = 0；滑块可微调
- 「不评分」= `score` 与 `maxScore` 都传 `null`，该题不计入总分（服务端行为，界面要说明）
- 满分默认 5，可改；`maxScore <= 0` 或 `score > maxScore` 前端就拦住（别等 400）
- 提交中禁用按钮；409 → 提示「这份卷子已经交过了」并跳结果页

**为什么这么设计**：接口把判分权交给客户端，但学生面对「得分 / 满分」两个空输入框是懵的。三个快捷档把「打分」降级成「判断对错」，滑块保留微调能力，这是最省心的形式。

| 改名 | `L4` | 行内变输入框；`renamed:false` → 「系统标签不能改名」 |
| 合并 | `L6` | 弹层：选目标标签 → 确认文案「「A」下的 12 道题会并入「B」，「A」将被删除」 |
| 删除 | `L5` | 确认文案「只解除关联，题目不会被删除」 |

**知识点 Tab**：同上，去掉「合并」（`K7` 无合并接口），列表用 `K1` + `K3`（题目数 + 得分率）。

**系统项**（`userid = 0`）：显示「系统」胶囊，三个操作按钮置灰，hover 提示「系统预置，不能修改」。

**搜索时的坑**：`L2`/`K4` 空关键词等于全量，所以清空搜索框时不要发请求，直接回列表。

## 5. 核心流程串起来

### 5.1 第一次使用（冷启动）

```
工作台空态 →「拍一张试卷」→ 录入页
  → 选图 → 框 3 道题 → 填题干/答案 → 提交
  → 成功页：「已存入 3 道题」[去补标签] [再录一张]
  → 补标签：逐题打开详情挂标签（或直接在录入卡片里选了，就不用补）
  → 工作台出现「待解决 3」→ 标记已解决
  → 分析页出现知识点 →「专项练习」→ 生成卷 → 作答 → 交卷 → 结果
```

### 5.2 日常复习（高频）

```
工作台「继续学习」→ 作答页（恢复上次进度）
  → 做完 → 交卷 → 评分抽屉 → 结果页
  → 结果页点最差的那题「查看原题」→ 看答案 → 回结果页
```

### 5.3 标签治理（低频）

```
整理 → 标签 → 搜索「三角」→ 发现「三角函数」「三角」重复
  → 合并：「三角」并入「三角函数」→ 列表刷新，题目数合并
```

## 6. 反冗余清单

明确**删掉**的东西，以及为什么。

| 删除项 | 原因 |
|---|---|
| 登录 / 注册 / 退出登录（3 个页面 + 侧栏账号区） | 接口无鉴权，登录了也没有任何东西会变。**已按你的决定保留登录页空壳**（不发请求），注册与退出删除 |
| 顶部导航里的「题目编辑」 | 编辑是详情页的状态，不是目的地。原页面进去是一片空表单 |
| 独立「标签管理」页 | 与知识点同质，合并成「整理」双 Tab |
| `FlowNav` 步骤导航（步骤 3/5 之类） | 产品不是线性流程：用户随时可能从分析页直接组卷。步骤条会误导「必须按顺序走」 |
| 假的「识别中…」进度条与整页 OCR 步骤 | 原来那套是假任务（没有接口）。现在识别真的在前端跑，进度来自引擎回调，**只在框选页露一条**，不占独立页面 |
| 独立的「识别结果校对」页 | 校对就该在填写卡片里做：左边裁切图、右边可编辑的题干，对照着改最快 |
| 工作台「近 7 天做题量」直方图 | 无时间字段，图只能是装饰 |
| 「导出 / 打印」按钮 | 无接口，`window.print` 排版不可控 |
| 「练一题 / 错题重做」 | 无单题作答接口 |
| 题库页的「按标签 / 知识点筛选」 | `Q4` 不支持，硬做等于假筛选 |
| 列表页每行的「编辑 / 删除 / 标签」图标按钮 | 一行塞 4 个图标是典型的冗余；统一「打开 ›」，操作在详情页 |
| 顶栏全局搜索 | 与题库页搜索重复 |
| 列表多选 + 批量操作 | 无批量接口 |
| 作答页的「计时器」 | 无时间字段，计了也无处存、无处比 |

**保留但改位置**：录入入口从「导航第 2 项」变成「顶栏主按钮」，因为它是动作不是页面。

## 8. 需要后端补的接口（影响体验，不阻塞本期）

按对体验的影响排序：

1. **`POST /api/question/{id}/answer`（单题练习）** —— 没有它，错题本只能「组卷复习」，不能「当场重做一题」。`recordPracticeAnswer` 已经写好，只差 Controller。
2. **`POST /api/question`（JSON 建题）** —— 解决「无图题」「一题多图」「建题时一次带答案+标签+知识点」。现在一次录入 5 道题要发 5 + 5×(1~3) 个请求。
3. **分页** —— `Q4`、`O6` 不分页，题库过千条时首屏会明显变慢。
4. **`answerrecord` 加时间列** —— 才能做「最近练习」「用时」「趋势」。
5. **`Q4` 支持 `tagId` / `knowledgePointId` 筛选** —— 才能做「按标签看题」。
6. **`O5` 校验状态** —— 已提交的卷不该能作废（前端已兜，但接口层更稳）。
7. **`Q6` 允许把 `source` / 答案清空为 null** —— 目前只能改成空字符串。
